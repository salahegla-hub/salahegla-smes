# التشغيل والنشر

## أولًا: لماذا تغيّرت طريقة النشر

الموقع السابق كان ملف `index.html` واحدًا. لا يمكن بناء نظام محتوى أو نسخة إنجليزية
أو صفحات تُولّد تلقائيًا فوق ملف HTML واحد — لذلك بُني المشروع الآن على **Astro**:
مولّد مواقع ثابتة يُخرج HTML صِرفًا (نفس سرعة الملف الثابت)، لكنه يبني الصفحات من ملفات Markdown.

النتيجة العملية: **تضيف مقالًا بملف نصّي واحد بدل تعديل HTML.**

---

## ثانيًا: الربط لمرّة واحدة (GitHub ← Netlify)

**١. ارفع المشروع إلى GitHub**
- ادخل https://github.com ← **New repository** ← سمِّه `salahegla-site` ← **Create**.
- في المستودع الجديد: **Add file** ← **Upload files** ← اسحب **محتويات** مجلد المشروع
  (ليس المجلد نفسه). **لا ترفع مجلد `node_modules` ولا `dist`.**
- اضغط **Commit changes**.

**٢. اربط Netlify بالمستودع**
- ادخل https://app.netlify.com ← مشروعك **salahegla.com**.
- **Project configuration** ← **Build & deploy** ← **Link repository** ← اختر GitHub ← اختر `salahegla-site`.
- أعدادات البناء (تُقرأ تلقائيًا من `netlify.toml`، وإن طُلبت يدويًا):
  - Build command: `npm run build`
  - Publish directory: `dist`
  - Node version: `22`
- **Deploy**.

**٣. من الآن فصاعدًا:** أي تعديل تحفظه على GitHub يُنشر تلقائيًا. لا سحب مجلدات بعد اليوم.

---

## ثالثًا: بديل مؤقّت (رفع يدوي)

إن أردت النشر فورًا قبل ربط GitHub: ارفع **محتويات مجلد `dist`** (وليس المجلد نفسه)
من صفحة **Deploys** في Netlify. لكن هذه الطريقة تعني أنك لن تستطيع إضافة مقال بنفسك،
لأن `dist` مبنيّ ولا يُحرَّر يدويًا. الربط بـGitHub هو ما يجعل الموقع قابلًا للتحديث بدونـي.

---

## رابعًا: النماذج (Netlify Forms)

نموذجا **طلب الاستشارة** و**النشرة البريدية** موصولان بـNetlify Forms تلقائيًا.
الرسائل تصل إلى: لوحة Netlify ← **Forms**.

**لتصلك تنبيهات على بريدك:** Netlify ← **Forms** ← **Settings & usage** ←
**Form notifications** ← **Add notification** ← **Email notification** ← ضع بريدك.

## خامسًا: النشرة البريدية التلقائية (خطوات التفعيل)

الموقع الآن **جاهز تقنيًا** للإرسال التلقائي: فيه خلاصة RSS لكل لغة:

- `salahegla.com/ar/rss.xml`
- `salahegla.com/en/rss.xml`

كل مقال جديد تنشره يظهر في هذه الخلاصة تلقائيًا. خدمات البريد تراقب الخلاصة
وترسل المقال الجديد للمشتركين **دون أي تدخل منك**. هذا اسمه RSS-to-Email.

### الخيار الموصى به: Buttondown (مجاني حتى 100 مشترك)

1. أنشئ حسابًا على buttondown.com.
2. من الإعدادات فعّل **RSS-to-Email** وضع رابط الخلاصة: `https://salahegla.com/ar/rss.xml`.
3. أرسل لي **رابط النموذج (embed / form endpoint)** من حسابك، وأنا أربط نموذج
   الاشتراك في الموقع به مباشرة — فيدخل كل مشترك جديد إلى قائمتك فورًا.

### البديل: Mailchimp (مجاني حتى ~500 مشترك)

نفس الفكرة: أنشئ الحساب ← أنشئ **RSS Campaign** بنفس رابط الخلاصة ←
أرسل لي رابط نموذج الاشتراك (Embedded form action URL) وأربطه.

### إلى أن تفعّل أحدهما

الاشتراكات الحالية تُحفظ في Netlify ← Forms، وتقدر تصدّرها ملف CSV
وتستوردها في الخدمة الجديدة لاحقًا — **لا يضيع أي مشترك**.

## سادسًا: الروابط القديمة

`netlify.toml` يحوّل تلقائيًا (301):

| الرابط القديم | إلى |
|---|---|
| `/` | `/ar/` |
| `/articles/infrastructure-sme-finance-gulf` | `/ar/articles/infrastructure-sme-finance-gulf` |
| `/articles/*` | `/ar/articles/*` |

فلا تُفقد أي روابط سبق أن شاركتها أو أرشفتها محركات البحث.

## سابعًا: التشغيل محليًا (اختياري)

يتطلّب Node.js نسخة 22:

```bash
npm install      # مرة واحدة
npm run dev      # معاينة على http://localhost:4321
npm run build    # بناء نسخة الإنتاج في مجلد dist
```
